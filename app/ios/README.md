# Ozimut for iPhone — the companion app

The live site (https://ozimut.com) in a web view, plus what a page cannot do: native notifications, files opened with
or shared to the app, the document scanner for map photos, the watch's routes from Apple Health, saving a file the site
makes. **It does not track** (that is Folloz, `track/`) and **it never shows anything about buying**. The contract is
[`docs/app/design.md`](../../docs/app/design.md); change it first, then this code. The owner's steps with Apple are in
`docs/app/setup.md`.

## What is here

| Path | What |
|---|---|
| `project.yml` | The Xcode project, generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) (`xcodegen generate`). The `.xcodeproj`, `App/Info.plist` and the entitlements file are written from it and are not in git. |
| `Core/Shell.swift` | What is pure, compiled into the app and the tests: `AppConfig` (base address, version, push environment), `NavPolicy` (where an address goes: the view, the phone's browser, nowhere; who may call the bridge), `BridgeMessage`, `Mime`, `JSON`. |
| `App/WebController.swift` | The web view: user agent ` OzimutApp/<version> (ios)`, the bridge's entry (`window.webkit.messageHandlers.ozimut`), the navigation policy, `window.open`, downloads to the share sheet, camera / compass permissions of the page, the site's alert and confirm dialogs, events kept until the page's first `info` call. |
| `App/AppModel.swift` | The bridge's calls (`info`, `pushState`, `pushRegister`, `saveFile`, `scanMap`, `healthRoutes`, `healthRoute`, `openSettings`), the push token, the files opened with the app (gathered 0.7 s, sent as one `files` event), a tapped notification (`push` event). |
| `App/MapScanner.swift` | `scanMap`: VisionKit's document camera, the first page as a JPEG. |
| `App/HealthRoutes.swift` | HealthKit workouts with a route, a route as GPX (read only; the same code as `track/ios`). |
| `App/OzimutApp.swift`, `App/Views/RootView.swift` | The app, its delegate (APNs, notification taps), the web view on screen, the no-network screen with « Réessayer ». |
| `Resources/` | The icon (the Ozimut mark, as `track/ios`), `PrivacyInfo.xcprivacy`, and `Localizable.xcstrings` + `<lang>.lproj/InfoPlist.strings`, **written by `tools/strings.py`** (French the reference, English the base, German « du », Spanish « tú »): edit the tables there, run `python3 tools/strings.py`, commit both. The workflow fails when they differ. |
| `Tests/ShellTests.swift` | Unit tests of `Core/`: allowed / external / blocked addresses, checkout hosts, the bridge's origin rule, message parsing, MIME types, safe file names. |

Identifiers: bundle `com.ozimut.app`, name « Ozimut », iOS 17+, iPhone only. No URL scheme, no universal links, no
extension, no watch app, no background mode.

## Building

There is no Mac in the project: GitHub Actions builds everything, `.github/workflows/app-ios.yml`.

- **`build`** (every push touching `app/ios/**`, and by hand): XcodeGen, an unsigned Debug build for the iOS simulator,
  the unit tests on an iPhone simulator. Compiler errors appear as annotations; the logs are kept a week.
- **`release`** (by hand only, « upload » ticked): a signed Release archive exported and uploaded to App Store Connect
  (TestFlight). Needs the repository secrets `APPLE_TEAM_ID`, `APP_STORE_CONNECT_KEY_ID`,
  `APP_STORE_CONNECT_ISSUER_ID`, `APP_STORE_CONNECT_KEY` (the `.p8` file's text); without them it says which are missing
  and uploads nothing. Signing is Xcode's automatic signing with that key (`-allowProvisioningUpdates`): the key needs
  the **Admin** role (it creates the distribution certificate and the provisioning profile), and the App ID
  `com.ozimut.app` must exist with its capabilities (below). The build number is the workflow run's number; the
  version is `MARKETING_VERSION` in `project.yml`.

On a Mac: `brew install xcodegen`, `cd app/ios && xcodegen generate`, open `Ozimut.xcodeproj`.

## What Apple's side needs (details in docs/app/setup.md)

- App ID `com.ozimut.app` with the capabilities **Push Notifications** and **HealthKit** (nothing else: no Associated
  Domains, no App Groups, no Sign in with Apple).
- An APNs auth key (`.p8`) for the server (`APNS_KEY`, `APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_TOPIC` = `com.ozimut.app`):
  the app only hands its token to the page, which posts it to `/api/push/native`. A Debug build says `env: "dev"`
  (Apple's sandbox service), a Release build `"prod"`; the entitlement `aps-environment` is `development` in
  `project.yml` and becomes `production` when the archive is exported for the App Store.
- The purpose strings (four languages, `tools/strings.py`): location while using the app (a page's « Ma position »,
  the map editor's field mode), camera (map photos and the scanner), photo library (choosing a map photo), microphone
  (a video recorded from a file field may carry sound), Health read (workout routes). The app asks for nothing at
  launch: each permission is asked when a page first uses it; notifications when the user turns them on in Réglages.

## Choices made

- **App-bound domain.** `WKAppBoundDomains` = `ozimut.com` (and the Debug host `OZ_DEV_HOST`), and the web view sets
  `limitsNavigationsToAppBoundDomains`: the site's service worker works in the app (offline pages, the Tracer's and
  the map editor's offline copies), and WebKit itself refuses any main-frame page of another domain — a second lock
  behind `NavPolicy`. Once the key is in the Info.plist, the script message handler and `evaluateJavaScript` exist
  **only** in a web view limited that way, so the limit is set whenever the base address is one of the bound domains.
  `track/ios` had left this out for fear that frames of other hosts (Cloudflare's anti-robot check, used by « Entrer
  sans compte ») would be refused; WebKit's limit is on the main frame's navigations, and frames are expected to load —
  **to be checked on the first device test**. If the check does not show, remove `WKAppBoundDomains` from `project.yml`
  (the app then works as `track/ios` did, without the service worker).
- **A Debug build elsewhere**: set `OZ_BASE_URL` (https, ending with `/`) and `OZ_DEV_HOST` (its host) together under
  `configs: Debug:`. A host that is not bound gets a web view without the limit, hence without the bridge. Plain `http`
  is not allowed (no App Transport Security exception is declared): use a tunnel or a staging address.
- **One origin.** The main frame shows the base address's scheme, host and port only; `www.ozimut.com`, any other site,
  `mailto:`, `tel:` go to the phone; checkout hosts (`NavPolicy.checkoutHosts`, the contract's `CHECKOUT_HOSTS`) are
  neither loaded — in any frame — nor handed to the browser. The bridge answers the main frame of that origin only.
- **No credential, no server call.** `pushRegister` returns the APNs token; the page registers it with its own session.
- **Events wait for the page.** `files` and `push` events are kept until the page's first `info` call after each
  document load (`appbridge.boot` calls it), so a file or a notification that started the app is not lost.
- **Files**: declared document types (GPX, FIT, TCX, KMZ, KML, PDF, images) put « Ozimut » in other apps' « Open in… »
  and share sheets for files; they are copied to the app's Inbox, read (80 MB at most each), deleted, and sent
  together when they came together.
- **Language**: the shell's few texts follow the phone's language; the pages follow the account's.
- **Privacy manifest**: no tracking, no required-reason API used by the app's own code (no `UserDefaults`, no file
  timestamps): add an entry to `PrivacyInfo.xcprivacy` before using one.

## Later

- A **Share Extension**, so that a photo shared from Photos or a file shared by an app that offers no « Open in… »
  reaches Ozimut (needs an App Group and a second target). Today a photo is taken or chosen from the page's file field.
- Universal links, so that a link of an Ozimut e-mail opens the app.
- The account's language for the shell's texts, and an iPad layout.

## Never run on a device

Nothing here has been compiled on the PC (Windows) nor run on a phone or a simulator before its first CI run: the first
`app-ios` run is its first compilation. To check on a real iPhone, in this order: the site loads and signs in (cookies
kept after a restart); « Entrer sans compte » (the anti-robot frame under the app-bound limit); the service worker
(`navigator.serviceWorker` in the Web Inspector of a Debug build); a link to another site opens Safari; a file field
offers camera, photos and files; « Scanner la carte »; a GPX opened from Files and from a watch maker's app; « Mes
sorties (Santé) »; saving an export (share sheet); notifications (permission, token registered, a test notification,
a tap opening its page — with the app closed too; needs the APNs secrets on the server, and HTTP/2 from the server to
Apple has never been verified); the no-network screen.
